# Arbor 生产就绪执行清单

> 目标：将 Arbor 桌面端、Web 端和同步服务端建设为可持续运营的生产系统。
>
> 使用方式：
> 1. 每个任务必须有唯一负责人、截止时间和验证证据。
> 2. `P0` 未全部完成时不得开放公众生产流量。
> 3. 验收不能只写“已完成”，必须附测试、监控截图、审计记录或恢复演练记录。
> 4. 正式发布版本必须通过本文末尾的“生产发布门禁”。

## 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 阻断正式生产；存在数据泄露、数据丢失、不可恢复或严重安全问题 |
| P1 | 允许受控试点，但正式生产前必须完成 |
| P2 | 生产质量、体验、性能和可维护性改进 |

## 完成状态字段

每个任务建议在项目管理工具中维护：

- 状态：未开始 / 进行中 / 待验收 / 已完成 / 阻塞
- 负责人
- 目标版本
- 依赖任务
- 验收证据
- 回滚方案
- 最后更新时间

# 二、P0：账户隔离与数据正确性

## ISO-01 桌面端按账号隔离本地数据

- [ ] 将单账号数据目录迁移为按用户隔离：

```text
%APPDATA%/Arbor/accounts/<user-id-or-hash>/
  arbor.db
  files/
  texts/
  annotations/
  blobs/
  usage.json
  ali/
```

- [ ] 首次登录时选择并迁移当前账号数据，迁移前创建完整备份。
- [ ] 切换账号后不得在新账号中显示上一账号的文献、聊天、记忆或用量。
- [ ] 退出登录后锁定上一账号的敏感视图。
- [ ] 新账号云端为空时，必须明确询问是否导入本机数据。
- [ ] 禁止默认把当前设备已有数据上传为新账号的初始快照。

验证场景：

1. 账号 A 导入文献并生成笔记。
2. 退出账号 A。
3. 登录云端为空的账号 B。
4. 确认 B 看不到 A 的文献，也不能自动上传 A 的数据。
5. 返回账号 A，确认数据完整。

验收：

```text
双账号端到端测试通过，并检查云端 B 的实体数量为明确选择后的结果。
```

## ISO-02 Web 端按账号隔离 IndexedDB 和 localStorage

- [ ] Web 数据键加入 `user-id` 或稳定的用户哈希命名空间。
- [ ] 不允许多个账号共用同一个 IndexedDB 文献库和 Blob 仓库。
- [ ] 登出时清除当前 User Token，但保留已加密的账号缓存策略必须明确。
- [ ] 新账号登录时禁止自动复用上一账号的工作副本。
- [ ] 完成浏览器多账号切换测试。

验收：

```text
同一浏览器先后登录 A、B、A，三个阶段的文献数量、Blob 哈希和用量记录均符合预期。
```

## ISO-03 首次同步和导入语义

- [ ] 登录页明确提供：

```text
使用云端数据并覆盖本机工作副本
申请合并本机数据
取消登录
```

- [ ] 云端为空且本机有数据时，不得自动上传。
- [ ] 云端有数据且本机有数据时，不得静默覆盖。
- [ ] 合并预览必须显示实体数量、冲突数量和操作范围。
- [ ] 合并或覆盖前创建本地和云端快照。
- [ ] 完成后提供可核验的同步结果摘要。

验收：

```text
覆盖、合并、取消、失败四类路径均有自动化测试。
```

## ISO-04 统一同步冲突规则

- [ ] 形成正式冲突矩阵，逐类定义：

```text
最后写入生效
字段级自动合并
数组去重合并
删除墓碑优先
必须人工确认
```

- [ ] 文档、聊天消息、笔记、摘录、任务、阿栗会话和设置分别配置策略。
- [ ] 不允许普通同步因版本落后无限阻断。
- [ ] 不可自动合并的数据必须进入明确 UI。
- [ ] 冲突解决记录必须包含用户、设备、时间和最终选择。

验收：

```text
双端并发修改、离线后重连、删除后修改、旧设备写入等场景全部通过。
```

## ISO-05 建立数据一致性检查任务

- [ ] 定期比较本地与云端实体数量、版本和哈希。
- [ ] 检查 Blob 引用是否全部存在。
- [ ] 检查 Outbox 是否长期堆积。
- [ ] 检查孤儿 Blob 和孤儿绑定。
- [ ] 在账户页提供“立即检查一致性”功能。
- [ ] 输出可导出的诊断报告，报告不得包含明文密钥。

验收：

```text
人工制造缺失 Blob、孤儿 Blob、版本冲突和游标缺口后，检查任务能准确报告。
```

# 三、P0：身份、Session 和 Web 凭据安全

## SEC-01 Web Session 改为 HttpOnly Cookie

- [ ] Access Token 和 Refresh Token 不再写入 localStorage。
- [ ] 使用 `HttpOnly; Secure; SameSite` Cookie。
- [ ] Refresh Token 仅发送到刷新接口。
- [ ] 实现 CSRF Token 或同源双重提交校验。
- [ ] 登出时服务端撤销 Session 并清除 Cookie。
- [ ] Session 接管后所有标签页立即锁定。

验收：

```text
浏览器开发者工具无法通过 JavaScript 读取 Refresh Token；
跨站请求、过期 Cookie 和被盗 Session 场景均被拒绝。
```

## SEC-02 Web 模型凭据保护

当前 Web 模型 API Key 存在浏览器本地，生产应二选一：

- [ ] 方案 A：服务端 BFF 代理模型调用，密钥使用 KMS/信封加密保存。
- [ ] 方案 B：保持浏览器直连，但明确 BYOK 风险，并至少使用 Web Crypto 加密和用户解锁口令。

正式生产推荐方案 A。

验收：

```text
浏览器网络面板和 localStorage 中不存在长期模型密钥；
密钥轮换、删除账号和密钥撤销均有审计记录。
```

## SEC-03 安全响应头

- [ ] 配置 CSP。
- [ ] 配置 HSTS。
- [ ] 配置 `X-Content-Type-Options: nosniff`。
- [ ] 配置 `Referrer-Policy`。
- [ ] 配置 `Permissions-Policy`。
- [ ] 配置 `frame-ancestors`。
- [ ] 检查 PDF.js Worker、WASM、Blob URL、WebSocket 和 OIDC 跳转兼容性。

验收：

```text
Mozilla Observatory 或内部扫描无高危项；
阅读、截图翻译、网页导入和 OIDC 在 CSP 下正常工作。
```

## SEC-04 登录和刷新限流

- [ ] 对 `/v1/auth/dev-login` 限流。
- [ ] 对 `/v1/auth/refresh` 限流。
- [ ] 对 OIDC 回调和交换接口限流。
- [ ] 按 IP、邮箱、设备和用户维度设置窗口。
- [ ] 对重复失败增加延迟和审计事件。
- [ ] 生产环境强制 `AUTH_DEV_MODE=false`。

验收：

```text
并发暴力登录和 Refresh Token 重放测试被限流并产生告警。
```

## SEC-05 业务接口限流与成本保护

- [ ] 对同步提交设置频率和批量上限。
- [ ] 对 Blob 准备与上传设置频率、并发和每日配额。
- [ ] 对 `/v1/web/fetch` 和搜索代理设置频率上限。
- [ ] 对每个用户的搜索次数、抓取量和模型调用成本建立预算。
- [ ] 对异常大查询和异常频繁请求返回明确错误码。

验收：

```text
单用户持续请求、批量创建、超大 Blob 和搜索滥用均按配置被限制。
```

## SEC-06 Session 和设备审计

- [ ] 记录登录、刷新、接管、撤销、主设备转移、快照恢复和账号删除。
- [ ] 记录设备名称、平台、IP 所属区域和 User-Agent 摘要。
- [ ] 日志不得包含 Token、API Key、文献正文和记忆正文。
- [ ] 用户可查看并撤销所有设备。
- [ ] 支持“撤销全部 Web Session”。

验收：

```text
安全审计表可查询；敏感字段扫描结果为零。
```

# 四、P0：Web 多标签页与离线一致性

## WEB-01 同步 Leader Lock

- [ ] 使用 `navigator.locks` 或 BroadcastChannel 选出唯一同步 Leader。
- [ ] 只有 Leader 执行 Outbox 提交和远端拉取。
- [ ] 非 Leader 标签页只接收更新事件并刷新 UI。
- [ ] Leader 关闭后平滑选出新 Leader。
- [ ] 所有标签页共享 Session 撤销和登出事件。

验收：

```text
同时打开 5 个 Arbor 标签页，观察 10 分钟：
只存在一个同步循环，无重复提交，无重复 Blob 上传。
```

## WEB-02 持久存储和淘汰处理

- [ ] 启动时申请 `navigator.storage.persist()`。
- [ ] 监控 `navigator.storage.estimate()`。
- [ ] 低空间时停止大文件导入并明确提示。
- [ ] IndexedDB 打开失败或版本冲突时显示恢复入口。
- [ ] 站点数据被清理后，可从云端重新恢复。

验收：

```text
模拟配额不足、数据库占用和清除站点数据，界面不白屏且给出恢复路径。
```

## WEB-03 PWA 版本与更新

- [ ] Service Worker 使用明确版本号或构建哈希。
- [ ] 新旧缓存能够安全清理。
- [ ] 新版本可用时提示刷新。
- [ ] 更新前保护未保存编辑内容。
- [ ] API 请求不进入静态资源缓存。

验收：

```text
旧版本页面打开时发布新版本，用户完成保存后再切换到新版本。
```

## WEB-04 禁用静默 fallback

- [ ] Web 未实现的 API 必须抛出 `UNSUPPORTED_IN_WEB`。
- [ ] 事件订阅缺失必须产生开发模式和测试错误。
- [ ] UI 捕获平台不支持错误并显示说明。
- [ ] 记录功能使用遥测，识别误缺失能力。

验收：

```text
故意调用桌面专属 API，页面显示明确提示且测试失败可定位，不出现静默空数组或 null。
```

# 十三、正式生产完成定义

只有同时满足以下条件，项目才可标记为“生产系统”：

1. 不同账号的数据在本地、浏览器和云端严格隔离。
2. Web Session 和模型凭据不存在 JavaScript 可读的长期明文存储。
3. 数据可自动备份、可验证恢复、可执行账号级删除。
4. 所有 P0 安全项关闭，无已知高危漏洞。
5. 同步、文件、登录和备份具备自动化故障恢复测试。
6. 有可观测性、SLO、告警、值班和回滚流程。
7. Web 和桌面端的核心研究工作流完成跨浏览器、跨版本验证。
8. 产品明确说明桌面端与 Web 端的能力边界。
